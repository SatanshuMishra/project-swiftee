# Decisions for Project Swiftie redesign

Questions the user settled. These are binding.

- 2026-10-06: The user instructed autonomous work with no clarifications ("You will work autonomously without any expectation of clarifications from me"; "The new UI/UX design above is simply a re-design/face-lift"). Every decision below marked "auto" was taken by the orchestrator with the recommended option under that instruction; the user reviews them in the pull requests.
- 2026-10-06: The design handoff is the Claude Design project 27738b4d-96c4-4170-87aa-d19b2f0407f2, folder design_handoff_project_swiftie/, copied byte-for-byte into docs/specs/project-swiftie-redesign.design/ so every builder reads the same reference.
- auto: The product name is "Project Swiftie" everywhere a person sees it; the request's "Project Swifte" is read as the design's spelling.
- auto: The work is a face-lift of v0.3.0. Every v0.3.0 feature stays; game rules (relisten schedule, answer matching, option generation, Lyrics or Lie decoy selection, the 15 achievement conditions) do not change.
- auto: Play together (host, join, lobby, multiplayer rounds, standings) is not built. The handoff says its networking is not designed, so the main menu shows two rows, Shuffle everything and Pick your eras, and no Play together row.
- auto: Because rooms do not exist, the nickname screen's explanation reads "It's only used in the app. You can change it in Settings." instead of the mockup's mention of rooms.
- auto: The edition is a compile-time flavour read from --dart-define=EDITION. The value "ana" builds the Ana edition; any other value, or none, builds the Open edition. Tests choose the edition through a Riverpod provider override.
- auto: Three release artefacts ship per version: macOS Open, Windows Ana, Windows Open.
- auto: latest.json keeps darwin-aarch64, darwin-aarch64-app, windows-x86_64 and windows-x86_64-nsis with unchanged meaning, and gains windows-x86_64-open. The macOS entries point at the Open build; the existing Windows entries point at the Ana build so copies already installed on Windows keep updating as the Ana edition; Windows Open copies read windows-x86_64-open.
- auto: The rename changes display names only. The bundle identifier com.swiftiequiz.desktop, the save folder, the Windows executable name swiftie-quiz.exe, the NSIS install folder, uninstall registry key and manufacturer key, and the Dart package name swiftie_quiz stay as they are, so installed copies update in place and saves load unchanged. The Windows installer removes the legacy "Swiftie Quiz" Start menu and desktop shortcuts when it creates the new ones.
- auto: The save format moves to version 4. Settings gain misuVisits ("often", "sometimes" or "off", default "sometimes") and nickname (null until set). Each achievement record gains song, albumId and trackId (null for records unlocked before version 4). A migration from version 3 adds those defaults.
- auto: Pick your eras shows the 12 curated eras of the design, in the design's order, with the design's era names and sub-labels, using covers and tracks from Deezer. Shuffle everything keeps v0.3.0's pool (the artist's Deezer top tracks).
- auto: Tonight's era is the curated era at index (day of year mod 12), where 1 January is day 1 in local time. Clicking it starts a 10-round Medium Sound game that ends on the Round summary screen.
- auto: "Ana's birthday" means v0.3.0's existing birthday window rule, unchanged. While it holds, the Ana edition opens the birthday card once per session about one second after the main menu appears. The letter text is v0.3.0's, verbatim.
- auto: The theme setting keeps v0.3.0's three values (Dark, Light, System) and default (Dark); colours are the design tokens, cross-fading over 300 ms.
- auto: macOS keeps the native traffic lights at the system's own position under a hidden, full-size-content title bar; Flutter paints the 28 px bar. The mockup's traffic-light coordinates illustrate the native position and are not reproduced by moving the buttons.
- auto: Windows hides the native title bar and paints a 32 px bar with its own minimise, maximise or restore, and close buttons, following the app theme, not the system theme.
- auto: The update badge moves into the title bar with the design's copy; the update dialog uses the design's layout with the real updater's version, notes, progress and errors.
- auto: Misu visits ship with every trigger except the multiplayer ones (close finish, multiplayer win). Often allows a game visit every 2 rounds, Now and then every 5, Off none; the Open edition's first-launch introduction always shows.
- auto: The record shelf replaces the cat gallery. Hovering an unlocked record plays about 5 seconds of its song from 8 seconds in at 70 % of the volume setting, through a freshly fetched Deezer preview; records without a track play nothing.
- auto: Instrument Serif (SIL Open Font License) is bundled as an asset; body text uses the platform's system font.
- auto: Builders prove behaviour with flutter tests and do not launch the app; the orchestrator runs the integrated macOS build and compares every screen in both themes against the mockup before reporting.
- auto: Work is built on the integration branch redesign/project-swiftie. The orchestrator first commits a routing scaffold there (final phase list and screen routing, placeholder screens and overlay slots, the Edition type and provider, the curated era table, and removal of the three old selection screens and the cat gallery), so the parallel steps never share a file. Every step's pull request targets that branch or the branch of the step group it builds on; nothing merges automatically.
- auto: Old palette field names on AppTokens stay as aliases of the new tokens so screens not yet rebuilt keep compiling; removing the aliases and other dead v0.3.0 widgets is a follow-up after every step merges.
- auto (replaces the AppTokens alias line above): The v0.3.0 AppTokens fields keep their exact v0.3.0 values while the design tokens are added beside them (the design's card token is named designCard), so screens and tests not yet rebuilt keep passing during parallel work; new code reads only the design tokens. Removing the v0.3.0 fields is the follow-up.
- auto: Reset clears the record shelf and stats only; settings (theme, volume, timers, Misu visits, nickname) and the updater state survive, matching the design's reset message.
- auto: A wrong answer's "track N" comes from the song's position on its album, derived from Deezer's album track order; shuffles drawn from top tracks show the era alone.
- auto: One modal stack arbitrates Esc and dialog-open state; game shortcuts and Misu's Esc act only when no dialog is open.
- auto: The routing scaffold also moves v0.3.0's shared layout helpers out of main_menu.dart and the Motion widgets out of result_feedback.dart into their own files, so the steps that rebuild those screens never break each other.
- auto: Step pull requests open only after the orchestrator has run the integrated build and checked the screens; any check not done is stated in each pull request.
- 2026-10-06: The spec review findings (15) were applied before dispatch; the user's standing instruction stands in for the read-back and spec approvals that interphase normally asks for.
