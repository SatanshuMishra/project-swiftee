# Decisions for the Flutter rewrite of Swiftie Quiz

Questions the user settled. These are binding.

## Standing directive (user, 2026-10-05)

The user asked for a fully autonomous run with no questions after one optional clarification round, which was not needed. Every decision below that is not quoted from the user was made under that directive, by asking in order: which option is most performant, most optimized, most secure, most reliable, and most in line with industry standards. Each such entry is marked "Decided under the standing directive".

## Settled by the user, word for word

- Rewrite the whole app from Tauri + React + Rust to Flutter. "This is a re-write. Not a re-design. Baring small details, the entire app remains the same."
- "From a design point of view everything stays exactly as today (for simplicity). The ONLY change to make to the design is the use of an updated improve `cat` model for both the static, loading indicator, etc. versions."
- Source of the new cat: Claude Design project 27738b4d-96c4-4170-87aa-d19b2f0407f2 ("Cat Asset Redesign Review").
- "For the back-end, the ONLY area to consider a change is with the open APIs used to fetch the lyrics, songs, album covers, etc." Requirements: "MUST be free, reliable and actively supported", new releases appear automatically with no app update.
- "Continue to ship this app ONLY for `macOS` and `windows`."
- "If the UI's for `windows` and `macOS` are separately designed under the current tech stack, use the `windows` version."
- "Re-working the CI pipeline and other aspects of the repo is part of this re-write to match the migration to `flutter`."
- Incorporate the updater fixes from PR #19 (merged to main as 8c0130e on 2026-10-05) and PR #20 (the v0.2.3 version bump, merged as b7d3e2d the same night; it changes only version numbers and the CHANGELOG).
- Ship with mitosis as draft pull requests for review; never merge.

## Decided under the standing directive

- Approach: one Flutter app at the repository root replaces `src/`, `src-tauri/` and the Node toolchain. Same screens, text, flows, timings, sounds, save file and update channel; only the cat icon and cat loader change. Rejected: Flutter UI over the existing Rust core through flutter_rust_bridge (two languages and an FFI layer for logic that is small, pure and easily ported; more build surface, no performance gain at this scale); keeping Tauri (not the request).
- State: flutter_riverpod 3 Notifiers holding hand-written immutable state classes with copyWith and hand-written JSON. No code generation (build_runner, freezed, json_serializable): generated files would collide across parallel branches and add a build step for no runtime gain.
- Audio: flutter_soloud (SoLoud C++ engine over FFI). It decodes the preview MP3 from memory, plays a slice from an offset with pause, resume, stop and volume, plays the quack, and reads decoded samples for the clip-selection energy profile. Rejected: just_audio and media_kit (no access to decoded samples, so smart clip selection could not be ported); platform channels to AVAudioEngine and Media Foundation (two native codebases).
- Clip-selection samples: read the decoded preview at an effective 8,000 samples per second (readSamplesFromMem with numSamplesNeeded = ceil(duration in seconds x 8000), average false) and compute the 250 ms RMS profile on those samples with sampleRate 8000. Equally spaced samples estimate frame RMS closely enough to rank quiet windows, at a fraction of the cost of full-rate PCM.
- HTTP: package:http with an injectable Client, HTTPS only, 10 second timeout for catalog and lyrics calls and 2 seconds for clip-selection lyric lookups, as today.
- Images and icons: flutter_svg for the cat icon, the 16 achievement cats and every Lucide icon the UI uses, shipped as SVG assets from lucide-static at the version matching lucide-react in package.json, so strokes match exactly. Album covers load through Image.network with the platform image cache.
- Window: window_manager opens the window at 1024 x 800, centred, minimum 686 x 571, titled "Swiftie Quiz", as tauri.conf.json does today.
- Fonts: the platform system font (SF Pro on macOS, Segoe UI on Windows), which is what today's Tailwind system-ui stack renders.
- Save file: unchanged format (version 3, camelCase JSON, pretty-printed) at the exact path Tauri uses, so players keep their progress: `~/Library/Application Support/com.swiftiequiz.desktop/save.json` on macOS and `%APPDATA%\com.swiftiequiz.desktop\save.json` on Windows. Atomic write through `save.json.tmp`, migration v1 to v3, a backup before migrating, three backups kept, list and restore from Settings.
- macOS: bundle identifier com.swiftiequiz.desktop, product "Swiftie Quiz.app", App Sandbox off with network client access (Tauri's app was not sandboxed; a sandboxed app could neither replace itself on update nor see the existing save path), ad-hoc signed as today, Apple Silicon only as today. Minimum macOS becomes 12 because Flutter does not support macOS 11.
- Updater: the Dart app speaks the Tauri updater protocol. Same latest.json URL and schema, same four platform keys, same minisign key pair (the existing TAURI_SIGNING_PRIVATE_KEY secrets), same artifact formats. So the first Flutter release installs onto every existing Tauri copy through that copy's own updater, and later Flutter releases update the same way. Behaviour follows PR #19: first check 1.5 s after launch then every 6 hours, never disturb an update in hand, skip version, remind later for 24 hours, cancel abandons the download, relaunch after install with an "installed, reopen the app" fallback. Rejected: Sparkle and WinSparkle (new key pair and secrets the run cannot create, a second feed while Tauri copies still read latest.json); no updater (strands users).
- Windows installer: NSIS, compiled by makensis in CI. It installs per user into `%LOCALAPPDATA%\Swiftie Quiz`, names the executable swiftie-quiz.exe, writes the same uninstall registry key and shortcuts as Tauri's NSIS template (saved at docs/reference/tauri-2.12-nsis-installer.nsi.hbs), removes the Tauri-era files it replaces, and honours /P, /S, /UPDATE, /R and /ARGS exactly as the Tauri updater passes them. Rejected: MSIX and Inno Setup (the installed Tauri updater launches an .exe with NSIS flags).
- Release signing: CI signs the .app.tar.gz and the setup .exe with the Tauri CLI's signer (`npx @tauri-apps/cli@2.12.1 signer sign`) using the existing secrets, and a Dart tool writes latest.json. No new secret is needed.
- CI: a Flutter workflow keeps the job name `CI OK` (the required check), pins every action by commit SHA as today, pins Flutter 3.47.5, runs format check, analyze with fatal infos, and tests on ubuntu-24.04, and builds and packages on macos-26 and windows-2025. The release workflow keeps tag-triggered draft releases, version and CHANGELOG checks, the dev-pubkey guard, manifest verification and SLSA attestations.
- Version: the rewrite is 0.3.0, recorded under an Unreleased heading in CHANGELOG.md until the release PR.
- Platform UI: the React UI has no operating-system branches (a search of src/ and index.html for platform, userAgent, darwin, windows, metaKey and window-chrome settings found none), so the one shared UI is ported. Where today's look comes from the platform's web engine rather than the app, the Windows (WebView2, Chromium) rendering wins: range sliders and the checkbox use Chromium's default accent #0075FF, confirm and alert prompts become in-app dialogs, scrollbars are thin overlay bars, dates use the system locale's short date.
- Repository: the web and Rust toolchain, its configs and the Tauri-specific project automation (agents, commands, hooks) are removed or rewritten for Flutter; CLAUDE.md, AGENTS.md, README.md, docs/INSTALL.md and receipts.config.json describe the Flutter app.
- Shipping: a feature branch `feat/flutter-rewrite` cut from main at b7d3e2d (PR #19 and PR #20 merged) carries the design assets and the reference template; mitosis opens one draft pull request per part against it, and one draft pull request takes `feat/flutter-rewrite` into main. Nothing is merged.

- Open APIs: keep Deezer (catalog, 30 second previews, covers) and LRCLIB (lyrics). Research on 2026-10-05 found no alternative that is free, keyless and permitted by its own terms for a quiz game: Spotify bans trivia games and removed previews, the Apple Music API is paid, iTunes Search terms forbid previews used for "independent entertainment value", Musixmatch synced lyrics are paid, Genius has no lyrics endpoint, MusicBrainz has no audio. Deezer listed the 2026-09-25 album the week it came out, and LRCLIB with its search fallback had synced lyrics for 16 of its 16 tracks.
- API reliability fixes carried into the rewrite, each a defect in today's client: follow Deezer's `next` link, because the artist now has 118 albums and `limit=100` drops the rest; treat a Deezer body carrying `error` (quota code 4 arrives with HTTP 200) as a failure; never cache a track's signed preview URL longer than its `exp` token allows, and on a 403 or an expired token re-read the track from `/track/{id}` once before giving up; send `User-Agent: SwiftieQuiz/<version> (+https://github.com/SatanshuMishra/project-swiftee)` to LRCLIB and Deezer; on LRCLIB 429 wait for `Retry-After` (at most 10 seconds) and retry once.
- Not added: a persistent offline catalog cache and a second provider. Both are new features; the request was to keep behaviour and pick the best providers.
- Bugs seen in the UI inventory that the port does not carry over, because Flutter's widgets do not reproduce them: the small cat loader cropped to a fragment (replaced by the v2 small drawing), the achievement toast timer restarting whenever another toast arrives, the update dialog's missing exit animation, and the birthday card's white body text on a white card in light theme (the text uses the foreground token). Every other behaviour, including dead code paths with no visible effect, is out of scope.
- Review fixes (spec review, 2026-10-05): asset checks use SHA-256 literals so they survive the removal of src/; verify-manifest compares asset names and waits for publish-manifest; the updater key is the single line `const updaterPublicKey = '...';` that the release check reads; release jobs that run Dart tools set up Flutter first; the quack goes through AudioController.playQuack with the 0.9 factor applied once in the engine; preview downloads live in lib/services/audio/preview_downloader.dart; the smoke launch uses a temporary HOME so it never touches the shared save; the system theme resolves at launch and on setting change only; only framework errors show the error screen; the retire Step comes after the release pipeline, owns dependabot.yml and claude-review.yml, deletes with rm -r, and rewrites receipts.config.json fully; shell scripts carry a shebang and are executable.
- The packaging-and-ci part stays stacked on the foundation so it builds in parallel with the logic part; the retire part therefore has two predecessors and its pull request targets the feature branch, showing only its own changes once the parts before it are merged.
- Approval (2026-10-05): the written spec and its 20 Steps were not shown to the user, who asked not to be asked; they were accepted under the standing directive after the independent spec review's 17 findings were all fixed and every interphase check passed. The tree guard reported only deliberate differences: the branch fast-forwarded from 8c0130e to b7d3e2d to include PR #20, and three build inputs created on purpose (design/cat-v2/cat-icon-v2.svg, design/cat-v2/cat-loader-v2.js, docs/reference/tauri-2.12-nsis-installer.nsi.hbs).
